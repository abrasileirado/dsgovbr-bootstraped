Cookiebar (<dsgovbr-cookiebar>)

Barra de consentimento de cookies do GOV.BR DS com comportamento: aviso no rodapé com Gerenciar cookies, Rejeitar cookies e Aceitar cookies; configurações por grupo (switches) num modal; e um botão flutuante, com ícone de cookie, que reabre as configurações depois da escolha. A aparência estática do aviso está em Auxiliares.

Uso

Esta página tem um <dsgovbr-cookiebar>: sem escolha salva a barra aparece no rodapé; depois da escolha fica só o botão no canto inferior esquerdo. Para ver a barra de novo, chame dsgovbrCookies.limpar() ou apague a chave dsgovbr-bootstrapped:cookies do localStorage. 

<script src="dist/dsgovbr-bootstrapped-cookies.js"></script>   <!-- no <head>: a API fica pronta cedo -->
...
<dsgovbr-cookiebar declaracao="/cookies">
  <dsgovbr-cookies-texto>Usamos cookies para melhorar sua experiência.</dsgovbr-cookies-texto>
  <dsgovbr-cookies-grupo nome="desempenho" rotulo="Desempenho">Medem o uso do site.</dsgovbr-cookies-grupo>
  <dsgovbr-cookies-grupo nome="funcionais" rotulo="Funcionais">Lembram suas preferências.</dsgovbr-cookies-grupo>
</dsgovbr-cookiebar>
<script src="bootstrap.bundle.min.js" defer></script>
  • O grupo necessarios (estritamente necessários) é criado sozinho: sempre ativo e bloqueado. Declare um grupo com o atributo necessario para trocar o texto dele.
  • Atributos: titulo (padrão "Aviso de cookies"), declaracao (link da Declaração de Cookies) e rotulo-declaracao. O texto do aviso vem do filho slot="texto" (aceita HTML).
  • O botão flutuante pode ser trocado por um acionador seu: qualquer elemento com data-dsgovbr-cookies-abrir abre as configurações, e o <dsgovbr-header cookies> já traz um botão de ação rápida assim. Com sem-botao no cookiebar o botão flutuante não aparece.
  • A barra não bloqueia a página (é um aviso, não um diálogo). As configurações abrem num modal do Bootstrap, então o bootstrap.bundle precisa estar carregado.
  • Legível no claro e no escuro: usa só os tokens do tema.

API e evento

window.dsgovbrCookies funciona também sem o elemento (para o site ligar ou desligar scripts por grupo): 

dsgovbrCookies.escolha()            // { necessarios: true, desempenho: false } ou null (sem escolha)
dsgovbrCookies.permitido("desempenho") // true só se a pessoa aceitou o grupo
dsgovbrCookies.definir({ desempenho: true }, "api")
dsgovbrCookies.limpar()             // apaga a escolha; a barra volta
dsgovbrCookies.abrir()              // abre as configurações

document.documentElement.addEventListener("dsgovbr:cookies", (e) => {
  // e.detail.grupos: { necessarios: true, ... } (null depois de limpar)
  // e.detail.origem: "aceitar" | "rejeitar" | "salvar" | "api" | "limpar"
  if (e.detail.grupos && e.detail.grupos.desempenho) carregarAnalytics();
});
if (dsgovbrCookies.permitido("desempenho")) carregarAnalytics(); // escolha de visitas anteriores

A escolha fica no localStorage (dsgovbr-bootstrapped:cookies); se ele estiver bloqueado, vale só para a página aberta. O evento dispara a cada mudança, não ao carregar: use permitido() para a escolha de visitas anteriores.

Usamos cookies para melhorar sua experiência e analisar o uso do site. Veja a nossa Medem o uso do site para melhorá-lo. Lembram suas preferências, como o modo escuro.

Diferenças conhecidas em relação ao GOV.BR DS

  • Não usa o BRCookiebar nem o JSON de categorias do GOV.BR DS: os grupos vêm do markup. A data de atualização da política e o consentimento por cookie individual não existem.
  • A escolha fica no localStorage do navegador, não em cookie; o servidor não a recebe sozinho.
  • O aviso é um painel fixo não modal (sem backdrop nem captura de foco), diferente da composição estática de Auxiliares, que usa .offcanvas.
  • Experimental: atributos, elementos filhos e API podem mudar antes da 1.0.
